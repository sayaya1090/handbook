# 문서-구현 불일치 및 구현 노트 (Discrepancy Log)

이 문서는 요구사항 및 설계 문서와 실제 코드 구현 간의 일시적인 불일치 또는 기술적 제약으로 인한 변형 사항을 기록합니다.

---

## 1. 세션 상태 모델 (SessionState)

| 항목 | 문서 상 정의 (docs/requirements.md) | 실제 구현 (shell-ui) | 상태 |
|------|---------------------------------|---------------------|------|
| **클래스 타입** | `sealed class` (Kotlin/Sealed) | `abstract class` | 🚧 기술 제약 (GWT 미지원) |
| **데이터 포함** | `Authenticated`, `InWorkspace` 가 사용자/워크스페이스 정보를 직접 소유 | 정적 상수 인스턴스만 제공. 실제 데이터는 `UserProvider`, `WorkspaceList` 를 통해 별도 조회 | 🚧 구현 단순화 |

**노트:** 현재 `SessionStateProvider`는 상태 전환 로직만 담당하며, 상태 객체 자체에 데이터를 담지 않습니다. 이는 상태 객체의 재사용성을 높이기 위함이나, 요구사항의 모델과는 차이가 있습니다.

---

## 2. Elasticsearch 검색 엔진 (Elasticsearch)

| 항목 | 문서 상 정의 (docs/architecture.md) | 실제 구현 (document-query) | 상태 |
|------|---------------------------------|---------------------|------|
| **형태소 분석기** | `Nori` 분석기 사용 명시 | 코드 상에 분석기 설정(`@Setting`, `@Mapping`) 누락 | ❌ 미구현 |
| **동적 매핑** | 스키마 정의를 참조한 자동 매핑 | `FieldType.Object` 로 단순 매핑 | 🚧 부분 구현 |

**노트:** Nori 분석기 적용은 인덱스 템플릿 또는 서버 설정을 통해 수행되어야 하며, 현재 코드 레벨에서는 명시되지 않았습니다.

---

## 3. GWT Java Record 지원

| 항목 | GEMINI.md 내 기술 지침 | 실제 GWT 지원 현황 | 상태 |
|------|---------------------|-------------------|------|
| **Record 사용** | "Java record 사용 가능 (GWT 2.12+)" | "GWT 2.13.0은 record 미지원" (디버깅 가이드와 충돌) | 🚨 문서 내 불일치 |

**노트:** GWT 2.12 이상에서 Java Record를 지원하나, 특정 빌드 환경이나 의존성 설정에 따라 컴파일 오류가 발생할 수 있습니다. 현재 프로젝트는 가급적 일반 클래스 사용을 권장합니다.

## 4. RBAC 연동 및 테스트

| 항목 | 요구사항 (3.3) | 실제 구현 | 상태 |
|------|--------------|---------|------|
| **UI 연동 테스트** | 역할 부여 및 권한 체크 UI 통합 테스트 | `WorkspaceManagementTest` 내 역할 부여 시나리오 누락 | 🚧 테스트 누락 |

**노트:** 도메인 모델(`Permission`, `Role`) 검증은 완료되었으나, 서비스 및 UI 레벨의 통합 검증이 부족합니다.

## 5. REST API 응답 상태 코드

| 항목 | 설계 규약 (Rest 관용구) | 실제 구현 (Controller) | 상태 |
|------|---------------------|---------------------|------|
| **생성(POST) 응답** | `201 Created` 권장 | `200 OK` (`@ResponseStatus(HttpStatus.OK)`) 사용 | 🚧 관용구 불일치 |

**노트:** `WorkspaceController.create` 등 주요 생성 API에서 `201` 대신 `200`을 반환하고 있습니다. 기능상 오류는 아니나 표준 REST 관용구와는 차이가 있습니다.

## 6. CQRS 서비스 명칭 접두사

| 항목 | 기존 문서 (architecture.md) | 실제 구현 | 상태 |
|------|---------------------------|---------|------|
| **클래스 명명** | 도메인 명칭 그대로 사용 (`DocumentService`) | `DocumentSearchService`, `DocumentCommandService` 등 기능별 접두사 사용 | ✅ 문서 갱신 완료 |

**노트:** 동일 도메인의 조회/명령 모듈 간 클래스 충돌 방지를 위해 접두사를 사용하고 있습니다. 2026-05-14 `docs/architecture.md`에 공식 반영되었습니다.

## 7. 자동 감사 규칙 (보완 예정)

- **에이전트 연동 섹션**: 모든 모듈의 `README.md`에 포함되었으나, `USECASE.md`의 시퀀스 다이어그램 정합성은 추가 검수가 필요함.
- **테스트 파일 확인**: `docs-keeper`가 보고한 "완료" 항목 중 일부는 실제 파일 경로와 클래스명이 미세하게 다를 수 있음 (예: `Application.java` vs `*Test.kt`).
